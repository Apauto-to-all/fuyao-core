# 分步装配引擎

> 一行启动用 `fuyao_app::start`；需要介入工具收集过程或自建 Provider 集合时分步装配。

## 前置条件

- fuyao.toml 配好 Provider + Model（见 [配置项参考](../参考/配置项参考.md)）
- .env 配好 API Key
- 构造好 `AgentPaths`（见 [Agent 身份与路径设计](../解释/Agent身份与路径设计.md)）

## 一行启动

```rust
use fuyao_api::{AgentPaths, EngineParams};

let app = fuyao_app::start(EngineParams {
    agent_paths: AgentPaths::default(),
}).await?;
```

内部完成：`init_engine` → `build_tool_registry` → 装配 `LoopGuardPlugin` → `Engine::new` → `App::new`。返回的 `App` 持 `Engine` + fan-in 出口（`mcp_manager` 与 `log_guard` 由 App 持有保活）。

## 分步装配

### 1. init_engine — 加载配置 → 注册 Provider → 批量构造 ProviderRegistry

```rust
use fuyao_api::AgentPaths;

let agent_paths = AgentPaths::default();
let fuyao_app::InitResult { provider, log_guard } =
    fuyao_app::init_engine(agent_paths.clone()).await?;
```

完成：`load_env` + `load_config` → `ensure_registered`（注册 Provider / Model）→ `init_logging` → `ProviderRegistry::from_registered`（批量构造所有已注册 Provider 的实例）。单个 Provider 实例创建失败仅 WARN 跳过；全部失败返 `NoProviderAvailable`。

### 2. build_tool_registry — 收集内置 + MCP 工具

```rust
let (tools, mcp_manager) = fuyao_app::build_tool_registry().await;
```

完成：`collect_builtin_tools`（内置工具，按 `[tools.enabled]` 过滤）+ `collect_mcp_tools`（MCP 工具，有配置时 `start_all` + `get_tool_entries`）→ `ToolRegistryBuilder::register_all` → `build`。返回的 `mcp_manager` 须由调用方持有保活。

### 3. 介入点 — 装配自定义插件工厂

```rust
use fuyao_core::PluginHost;

// 装配插件工厂（每个 session 启动时会调 create_instance 生成独立实例）
let mut plugin_host = PluginHost::new();
plugin_host.add(Box::new(fuyao_guard::LoopGuardPlugin::new()));
// plugin_host.add(Box::new(自定义插件工厂));
```

> 自定义工具的注入：内置工具 + MCP 工具的收集逻辑在 `fuyao-app` 内部模块（`tools.rs` / `mcp.rs`）为私有。若需要追加自定义工具，推荐两种方式：
>
> 1. **构造后注入**：用 `fuyao-tools::all_tools()` 拿内置工具自己组装 `ToolRegistryBuilder`，再 `register(自定义工具)` 后 `build`
> 2. **在 Engine 之外管理**：把自定义工具逻辑做成独立进程 / MCP server，经 `[mcp_servers]` 配置接入

详见 [加自定义工具](加自定义工具.md)。

### 4. Engine::new — 启动引擎

```rust
use fuyao_api::EngineParams;

let engine = Engine::new(
    EngineParams { agent_paths },
    provider,         // ProviderRegistry
    tools,            // ToolRegistry
    plugin_host,      // PluginHost
).await;
```

引擎启动后：DB 已打开、调度表为空、per-session 出站通道在每次 `create_session` 时按需建立。可开始 `create_session` / `resume_session`。

### 5. App::new — 装配 fan-in 单一出口（可选）

`Engine` 出站是 per-session 的（每个 session 返独立 rx）。若想像一行启动那样拥有单一出口，用 `App` 包装：

```rust
use fuyao_app::App;
use std::sync::Arc;

let engine = Arc::new(engine);
let app = App::new(engine, mcp_manager, log_guard);
```

`App` 为每个主 session spawn forwarder 把 per-session rx 汇聚到 `fan_out`，经 `App::recv` 对外暴露单一出口。子任务 session（`create_child_session`）的 rx 不进 fan_out，返调用方独占消费。

## 验证

```rust
use fuyao_api::{InputEvent, ModelConfig, SessionParams};
use fuyao_api::message::input::{UserMessage, UserPayload};
use fuyao_api::message::{EventBase, UserMessageMode, UserMessageSource};

// 创建对话（App 形态：返 session_id，rx 由内部 forwarder 消费进 fan_out）
// 主对话模型在此时显式提供（ModelConfig.model_id，String 必填），引擎不提供隐式兜底
let session_id = app.create_session(SessionParams {
    model_config: ModelConfig {
        model_id: "deepseek/deepseek-v4-flash".to_string(),
        ..Default::default()
    },
    ..Default::default()
}).await?;

// 发消息
let user_msg = UserMessage {
    base: EventBase::default(),
    payload: UserPayload {
        content: "你好".to_string(),
        mode: UserMessageMode::Guide,
        source: UserMessageSource::User,
    },
};
app.send(&session_id, InputEvent::User(user_msg)).await?;

// 接收事件流（App::recv 单一出口）
while let Some(event) = app.recv().await {
    match event {
        fuyao_api::OutputEvent::Chunk(c) => {
            if let Some(t) = c.payload.content { print!("{}", t); }
        }
        fuyao_api::OutputEvent::Assistant(_) => break,
        _ => {}
    }
}

// 优雅关闭
app.shutdown().await;
```

## 优雅停机

应用退出时调 `App::shutdown`（消费 `self`），实现有序清理：

```rust
app.shutdown().await;
```

完成：`engine.shutdown()`（cancel 所有 session task → 落 in-flight 状态 → JoinSet 并发等待 → 总 10s 超时 abort 兜底 → 刷新 SQLite 查询计划统计，失败仅告警不阻断）→ 等 forwarder 退出 → `mcp_manager.stop_all()`（每个 MCP 连接 rmcp `close_with_timeout` 优雅关闭）→ drop App 让 `log_guard` flush 日志。
