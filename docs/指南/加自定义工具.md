# 加自定义工具

> 定义工具 Schema → 实现 handler → 收集进 ToolRegistry → 注入 Engine::new → 验证。
>
> **关键**：所有工具必须在 `Engine::new` 前收集成 `ToolRegistry` 一次性注入。

## 1. 定义工具 Schema

工具定义是中立三要素（`name` / `description` / `parameters` 平铺，wire 形态由供应商适配层编码）。用 `ToolDefinition::new` 快速构造骨架，再补 parameters：

```rust
use fuyao_api::{ToolDefinition, ToolParameters, ToolParameterProperty};
use std::collections::HashMap;

// 构造参数 schema
let mut properties = HashMap::new();
properties.insert("city".to_string(), ToolParameterProperty {
    kind: "string".to_string(),                // 字段名是 kind（serde rename = "type"）
    description: "城市名".to_string(),
    ..Default::default()
});

// ToolDefinition::new 返回 owned 实例，可直接 mutate parameters
let mut definition = ToolDefinition::new("get_weather", "查询指定城市的天气");
definition.parameters = ToolParameters {
    kind: "object".to_string(),
    properties,
    required: vec!["city".to_string()],
};
```

## 2. 实现 handler

handler 写规范签名 `async fn(参数, 上下文, 取消令牌) -> ToolOutput`，返回统一结果信封：

```rust
use fuyao_api::{CancellationToken, ToolCallContext, ToolOutput, tool_handler};

// 第三参数 cancel：本次工具批次的中断信号。
// 短任务可忽略（下划线占位，被中断时引擎自动 abort 兜底）；
// 长任务应在内部 select! 监听 cancelled()，命中后优雅收尾（杀子进程等）。
async fn get_weather(
    args: serde_json::Value,
    _ctx: ToolCallContext,
    _cancel: CancellationToken,
) -> ToolOutput {
    let city = args["city"].as_str().unwrap_or("unknown");
    ToolOutput::ok(serde_json::json!({ "result": format!("{city} 晴天 25°C") }))
}

// tool_handler 把规范签名异步函数包装成 ToolFn（Arc / Box::pin 的类型体操集中在此）
let handler = tool_handler(get_weather);
```

- **tool_handler**：一步包装成 `ToolFn`，`Arc` / `Pin<Box<dyn Future>>` 的类型体操集中在一处，工具站点零样板
- **Arc**：handler 会被 clone 到并行任务（多 session 并发 + session 内并行）
- **返回 ToolOutput**：统一结果信封三变体——`Value`（JSON 对象，多数工具）/ `Text`（纯文本，如子代理最终回复）/ `Err`（错误，wire 恒有 `"error"` 键），wire 序列化由 `to_wire` 单点完成
- **parse_args**（可选）：参数字段多时定义 `#[derive(Deserialize)]` 结构体，经 `fuyao_api::parse_args` 类型化解析，常见 serde 错误自动译为中文并附修正建议
- **cancel 参数**：工具批次的中断信号，长任务据此优雅收尾（机制见 [工具系统设计](../解释/工具系统设计.md) 的中断交互）

## 3. 收集进 ToolRegistry

用 `ToolRegistryBuilder` 链式构造：

```rust
use fuyao_api::ToolEntry;
use fuyao_core::ToolRegistryBuilder;

// ToolEntry::new(定义, handler, child_invisible)——第三参数 false 表示对子 session 可见
let entry = ToolEntry::new(definition, handler, false);

let mut builder = ToolRegistryBuilder::default();
builder = builder.register(entry);
// 也可 register_all 批量注入
let tools = builder.build();
```

## 4. 注入 Engine::new

```rust
let engine = Engine::new(
    EngineParams { agent_paths },
    provider,         // ProviderRegistry
    tools,            // 含自定义工具的 ToolRegistry
    plugin_host,      // PluginHost
).await;
```

引擎持有 `Arc<ToolRegistry>`，所有 session task 共享同一份工具表。

## 验证

```rust
use fuyao_api::{InputEvent, ModelConfig, OutputEvent, SessionParams};
use fuyao_api::message::input::{UserMessage, UserPayload};
use fuyao_api::message::{EventBase, UserMessageMode, UserMessageSource};

// 创建会话时显式提供 model_id（String 必填），引擎不提供隐式兜底
let session_id = app.create_session(SessionParams {
    model_config: ModelConfig {
        model_id: "deepseek/deepseek-v4-flash".to_string(),
        ..Default::default()
    },
    ..Default::default()
}).await?;

let user_msg = UserMessage {
    base: EventBase::default(),
    payload: UserPayload {
        content: "北京天气怎么样？".to_string(),
        mode: UserMessageMode::Guide,
        source: UserMessageSource::User,
    },
};
app.send(&session_id, InputEvent::User(user_msg)).await?;

// 观察事件流：ToolCall(tool_name="get_weather") → ToolResult → Assistant
while let Some(event) = app.recv().await {
    match event {
        OutputEvent::ToolCall(tc) => println!("调用工具: {}", tc.payload.tool_name),
        OutputEvent::ToolResult(tr) => println!("工具结果: {}", tr.payload.content),
        OutputEvent::Assistant(_) => break,
        _ => {}
    }
}
```

## 并发安全（自主决策）

- **多 session 并发**：多个 session 同时调 `get_weather`，各自调用、各自拿结果（session id 标签区分不串话）
- **session 内并行**：若 LLM 一次返回多个 `get_weather`（不同 city），它们会被并行执行（`get_weather` 默认不在 `parallel_safe`，会走串行；如果工具是只读无副作用可加进 `[tools.runner.parallel_safe]`）
- **并发安全是工具自己的责任**：handler 内若访问共享资源（DB、文件），工具自己加锁/排队
