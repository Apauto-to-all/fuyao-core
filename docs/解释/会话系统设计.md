# 会话系统设计

> 本文解释 SQLite 持久化、上下文压缩、Todo 管理与 SessionPlugin。API 签名见 `cargo doc --workspace`。

## 经 Plugin 接入

会话系统通过 SessionPlugin（impl Plugin）注入引擎，而非引擎硬编码依赖：

```text
SessionPlugin 注册的钩子：
  before_llm      → 注入压缩消息 / skip_tools
  output_observe  → 持久化 User / Assistant 消息
  send_input      → 拿 Sender（为压缩后的消息注入做准备）
```

> 这是 fuyao-core 不依赖 fuyao-session 的原因——会话持久化是可插拔能力。详见 [Hooks 与 Plugin 设计](Hooks与Plugin设计.md)。

## SessionContext：会话状态管理

```text
SessionContext {
    agent_paths: AgentPaths
    model_id: Option<String>
    session_id: Option<String>
    // 内部：SessionManager（缓存 + 工厂）
}
```

懒初始化：`ensure_session()` 时——已有 > 加载已有 > 新建。

## SessionManager：全局缓存工厂

```text
SessionManager（全局单例 + 按 agent_paths 缓存）
  └─ SQLiteStore（底层存储）
```

`get_session_manager()` 全局工厂，按 agent 路径缓存 SessionManager 实例——同一 agent_id 复用连接池。

## SQLiteStore：底层存储

- per-agent 隔离：每个 agent_id 独立的 sessions.db（见 [Agent 身份与路径设计](Agent身份与路径设计.md)）
- 连接池：`max_connections`（默认 5，可配）
- busy_timeout：默认 5s
- WAL 模式（高并发读写）+ 外键启用

### 表结构（4 张表）

```text
sessions（会话）
├── id              TEXT PK       会话 ID（8 位 UUID 截断）
├── parent_session_id TEXT FK→sessions.id  父会话（压缩分裂链）
├── started_at      REAL NOT NULL  开始时间戳
├── ended_at        REAL           结束时间戳
├── message_count   INTEGER       消息总数
├── tool_call_count INTEGER       工具调用总数
├── total_*_tokens  INTEGER       累计 token（prompt/completion/reasoning/cached）
├── total_cost      REAL          累计费用
├── title           TEXT          会话标题
└── system_prompt   TEXT          系统提示词（冻结）

messages（消息）
├── id              INTEGER PK AUTOINCREMENT
├── session_id      TEXT NOT NULL FK→sessions.id
├── model_id        TEXT          模型 ID
├── role            TEXT NOT NULL  user/assistant/system/tool/developer
├── content         TEXT          消息内容
├── reasoning       TEXT          推理内容
├── tool_call_id    TEXT          工具调用 ID（tool 角色）
├── tool_calls      TEXT          工具调用列表（JSON）
├── tool_name       TEXT          工具名称
├── *_tokens        INTEGER       单条 token 用量
├── cost            REAL          单条费用
├── finish_reason   TEXT          stop/tool_calls/length
└── timestamp       REAL NOT NULL

todos（待办）
├── id              TEXT          复合 PK (id, session_id)
├── session_id      TEXT NOT NULL FK→sessions.id
├── content         TEXT NOT NULL  任务描述
├── status          TEXT DEFAULT 'pending'  pending/in_progress/completed/cancelled
├── sort_order      INTEGER       排序（=优先级）
├── created_at      REAL NOT NULL
└── updated_at      REAL NOT NULL

schema_version（版本管理）
└── version         INTEGER       当前版本 1（迁移预留）
```

### 索引

| 索引 | 表 | 列 | 用途 |
|------|----|----|------|
| `idx_sessions_parent` | sessions | parent_session_id | 压缩分裂链查询 |
| `idx_sessions_started` | sessions | started_at DESC | 按时间列会话 |
| `idx_messages_session` | messages | (session_id, timestamp) | 核心读路径：取会话消息流 |
| `idx_todos_session` | todos | session_id | 取待办列表 |

> token 冗余设计：messages 存单条 token，sessions 存累计 token（逐条累加维护）。
>
> `parent_session_id` 自引用实现压缩分裂链——压缩时开新 session 指向旧 session。

## 上下文压缩（CompressionTracker）

### 触发条件

```text
每轮 ReAct 后（output_observe 捕获 Assistant 消息时）检查：
  prompt_tokens >= 模型上下文窗口 × threshold（默认 0.85）
    │
    ├── 是 → 启动压缩
    └── 否 → 继续
```

- `context_length` 优先从模型注册表（`limit.context`）解析，查不到回退 `fallback_context`（默认 128000）
- `prompt_tokens == 0` 时直接跳过（无法判断占用比例）

### 压缩流程

```text
① inject_compression_guide
   │  通过 PluginEmitter 注入 Guide 队列消息（身份 "compressor"）
   │  内容 = 固定的压缩系统提示词
   │  设 compression_in_progress = true
   │
② before_llm 钩子
   │  skip_tools = true（压缩轮次禁止调工具，AI 只做摘要）
   │
③ 引擎自动消费 Guide 消息 → LLM 生成摘要（无 tool_calls 的 Assistant）
   │
④ output_observe 捕获摘要响应
   │  handle_compression_complete：
   │    a. 定位压缩引导消息位置
   │    b. 之前的消息 = 原始对话（待压缩）
   │    c. 保留窗口 = min(config_window, original.len() / config_window)
   │    d. expand_for_integrity（向前扩大窗口确保 assistant+tool 块完整）
   │    e. split_session：结束旧 session → 开新 session → 写入 [摘要 + 保留窗口]
```

> **保留窗口公式** `min(config_window, len / config_window)`：小对话（消息数 ≈ window）少保留，大对话保留完整 window。当消息数 = 2 × window 时才保留完整窗口。

### 压缩系统提示词

要求 LLM 输出固定 Markdown 结构：目标 / 约束 / 进度 / 关键决策 / 下一步 / 关键上下文 / 相关文件。**禁止包含密钥**（遇密钥替换 `[已脱敏]`），**禁止调工具**。

### expand_for_integrity

保留窗口可能切断 assistant+tool 块（assistant 发起 tool_call 但对应的 tool_result 在窗口外）。`expand_for_integrity` 向前扩大窗口，检查每个 assistant 的所有 `tool_call_id` 是否都有对应的 result 消息，缺失则继续向前扩大。

### split_session

结束旧 session（`end_reason = "compression"`）→ 创建新 session（`parent_session_id` 指向旧 id）→ 写入摘要消息 + 保留窗口消息 → 自动从压缩消息累加 token/cost 统计。旧 session 数据保留，可追溯压缩分裂链。

配置：`[session.compression]`（见 [配置项参考](../参考/配置项参考.md)）。

## 费用计算（calculate_cost）

每轮 LLM 响应的 Assistant 消息经 `SessionManager::add_message` 自动计算费用（Decimal 精确累加后转 f64，避免浮点误差）。

### 计费公式

```text
费用 = 输入费用 + 输出费用 + 缓存费用

输入费用 = (prompt_tokens - cached_tokens) × input_price / 1M
输出费用 = 按 reasoning_price 是否存在分两种：
  ① reasoning_price 存在且 ≠ output_price：
     non_reasoning = completion - reasoning
     输出 = non_reasoning × output_price + reasoning × reasoning_price
  ② reasoning_price == output_price 或不存在：
     输出 = completion × output_price
缓存费用 = cached_tokens × cache_price / 1M
```

- **缓存 token 扣除**：输入费用排除缓存命中部分（`prompt - cached`），缓存单独按 `cache_price` 计费
- **梯度价格 tier**：`tiers` 按 `max_tokens` 排序，取第一个 `prompt_tokens ≤ tier.max_tokens` 的区间，无匹配取最后一个。tier 内有值的字段覆盖平铺价格

### token 累计

每条消息的 token 逐条累加到 session 级别的 `total_*_tokens`。`cached_tokens` 单独累计到 `total_cached_tokens`，不从 prompt 中扣除（两者独立累加，费用计算时才扣除）。`split_session` 从压缩消息重新累加统计。

## 关键设计决策

### 为什么经 Plugin 接入而非引擎内置？

会话持久化是可选能力。经 Plugin trait 接入，引擎内核零感知存储细节。替换实现（如换 PostgreSQL、换内存存储）只需替换 Plugin，不改引擎。

### 为什么 per-agent 隔离 sessions.db？

不同 agent_id 是独立 Agent 实体（数据隔离单元）。它们的会话历史不应交叉——coder 的对话不应出现在 reviewer 的会话里。per-agent 隔离确保数据安全。

### 为什么压缩用 split_session 而非滑动窗口？

滑动窗口简单但丢失早期上下文。split_session 把旧消息总结为摘要，保留信息密度的同时控制 token 数。开新 session 确保不会无限增长。

### 为什么 SessionManager 按 agent 路径缓存？

不同 agent_id 有不同的 sessions.db（per-agent 隔离）。缓存 SessionManager 实例避免每次操作都重建连接池——同一 agent_id 的多次操作复用同一连接。
