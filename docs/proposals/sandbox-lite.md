# 储备提案：轻量沙盒方向

**优先级**：低（储备，供后续参考）
**状态**：定位决策已定——不做完整沙盒

## 定位前提（已定决策）

- **无人值守是产品定位**：不做审批流（人工确认高危操作），不引入「询问用户」
  类工具——风险决策不靠人挡，靠静态防护 + 可恢复性兜底
- **轻量是核心约束**：Docker 每会话一容器、Windows 受限令牌等完整沙盒方案
  与「独立轻量引擎 SDK」定位冲突，明确不做

## 现有防护盘点（已落地，无需重做）

| 层 | 机制 | 位置 |
| --- | --- | --- |
| 文件路径 | 敏感路径前缀 / 设备文件 / 二进制扩展 / 写根限制（`FUYAO_WRITE_SAFE_ROOT`）/ 框架内部路径 | fuyao-tools `file/safety.rs` |
| 命令 | 危险命令分级检测 / 工作目录校验 / 环境变量屏蔽 | fuyao-tools `terminal/safety.rs` |

| 行为 | 循环检测 + 四级处置（Warn/Inject/Interrupt/Abort） | fuyao-guard 插件 |

## 储备方向（按性价比排序）

### 1. per-session bash 禁网开关

会话级配置项（默认放开），开启后该会话的 bash 子进程走无网环境：
- Unix：`unshare -n`（需权限）或空代理环境变量组合
- Windows：无原生 namespace 隔离，只能靠代理环境变量指向 `127.0.0.1:1` 之类的
  软限制（可被绕过，文档需诚实标注）

软限制不完美，但拦的是「模型失控外联」这类主要风险面，实现成本极低。

### 2. 命令静态检测的持续强化

现有危险命令检测是规则集，可持续补：fork 炸弹模式、管道执行下载
（`curl | sh`）、sudo 提权链、磁盘填充（`dd` 到块设备）等。零架构成本，
按实际遇到的 case 增量补规则即可。

### 3. 可选 Docker bash 执行器（远期，feature-gate）

确有强隔离需求的部署方，可提供「bash 经 docker 容器执行」的可选后端：
workspace 挂载进容器、执行完即销毁。做成装配期可选能力（不默认、不拖累
无 Docker 环境），定位是给运维型用户的选项，不是默认安全模型。

## 不做清单（防将来重复提议）

- 审批流 / 人工确认门：与无人值守定位冲突，不做
- 完整 OS 级沙盒（seccomp profile / Windows AppContainer / 每 session VM）：
  成本与定位不匹配，不做
