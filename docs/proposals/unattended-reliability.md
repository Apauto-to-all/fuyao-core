# 储备提案：无人值守可靠性

**优先级**：中（无人值守定位的必答题，按需逐项储备）
**状态**：现状盘点完成，未立项

## 定位前提（已定决策）

产品按无人值守运行：事件流另一端没有人在实时消费 `OutputEvent`、做审批、
拍板重试。一切"人肉兜底"路径都不存在——可靠性必须由引擎自身闭环：
**该重试的自己重试、该停的自己停、该叫人的必须叫到人**。

## 现状盘点（已落地的可靠性资产）

| 维度 | 机制 | 位置 |
| --- | --- | --- |
| LLM 调用 | 可恢复错误（限流 / 超时 / 连接 / 5xx）退避重试，前发 Retry 事件 | fuyao-provider `RetryRunner` |
| MCP | 长连接自动重连 + 实例级熔断 | fuyao-mcp `CircuitBreaker` |
| 失控防护 | 工具重复 + 文本自相似检测，四级处置（Warn / Inject / Interrupt / Abort），中断 ≥3 次升 Abort | fuyao-guard `LoopGuardPlugin` |
| 压缩 | 失败发 Compression Failed 事件，不静默跳过 | react/compression |
| 中断 | 三段收尾：先发 Interrupt 通知再补增量结果落库，不留半截状态 | interrupt 模块 |
| 持久化 | SQLite WAL + 事件级落库，无常驻内存历史 | `SessionStore` |
| 崩溃残留 | 悬挂 tool_calls 读时配对兜底（主对话与压缩同口径） | `pair_missing_tool_results` |
| 配置 | fail-loud：坏配置启动即报错，错误附可用列表 | 配置加载层 |

结论：单点故障的"自动恢复"已有底子；缺的是**预算熔断、失败终态处置、
告警外呼、崩溃自愈**四类"无人接管"场景。

## 储备方向（按优先级）

### 1. 预算熔断（最优先）

无人值守最大的风险不是失败，是**跑飞**：模型循环调用、上下文膨胀、费用无限
累积。计费与 token 统计已在（Decimal 精确、事件级落库），缺的只是
「阈值 → 停」：

- 三条线：单会话费用上限 / 单会话总 token 上限 / 单 turn 最大轮数
- 触发即 Abort（复用 `LoopSeverity::Abort` 语义与中断协议收尾），发 Error 事件
- 配置独立成段（如 `[guard.budget]`），默认关闭——配了才启用，阈值必填
- 实现面：guard 插件（观察事件累计 + 拦截）即可承载，不动内核

### 2. 失败终态处置（重试耗尽之后）

`RetryRunner` 耗尽后错误冒泡为 turn 失败 + Error 事件——有人值守时人来决定
下一步，无人值守下这条事件等于"死信"。需要会话级失败策略：

- 可配置：失败后自动整轮重试 N 次（指数退避）/ 重试耗尽将会话挂起并触发告警
- 可选：备用模型降级（主模型连续失败 → 换备）——注意与前缀缓存红线的
  关系（换 endpoint 缓存即失效），只作兜底不作常态
- 死信语义：会话进入明确的 Failed 终态（可查询、可恢复），不是默默停在半路

### 3. 告警外呼

事件流没人消费 = 没有告警。日志规范已定「ERROR 半夜叫醒测试」，但只写文件
不叫人：

- 通知插件（hooks 插件机制现成）：观察 `OutputEvent::Error` / 预算熔断 /
  Abort 终态，转发 webhook（飞书 / 钉钉 / 自建端点）
- 插件化保轻量：内核只保证事件完整，通道实现归插件与上层应用

### 4. 崩溃自愈

进程重启后现在是"等人 resume"，无人值守下需要引擎自己接手：

- 启动时检测非正常退出的活跃会话（会话状态标记 running 未收尾），
  按策略自动 resume 或标记 Interrupted 待上层决策
- DB 健康检查：启动时 `PRAGMA quick_check`；定期备份快照（sessions.db 是
  唯一数据源，损坏即全失）
- 磁盘满：落库失败的明确错误事件，杜绝静默丢消息

### 5. 看门狗（长尾）

- turn 级整体时长上限（防流式悬挂 / 工具组合卡死）
- 各工具超时基线对齐（bash / webfetch 已有，其余逐项自查）

## 边界与原则

1. 一切熔断 / 重试策略**可配置且默认克制**——无人值守不等于激进自愈，
   「停得明确」优先于「猜着重试」
2. 处置动作复用既有机制（`LoopSeverity::Abort`、中断协议、事件变体），
   不为可靠性另起一套执行路径
3. 告警通道插件化，内核不内置任何具体 IM / webhook 依赖
